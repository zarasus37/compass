## Work and decisions

Polar's planning consultation recommended a trigger plus application intent and a three-part split. DR-FIN-08 and 00-DESIGN.md now define FIN-02-A foundation, FIN-02-B writer intent/atomicity, and FIN-02-C reset/projection/diagnostics. The parent FIN-02 remains backlog and incomplete. Its confirmed report is preserved verbatim. This test/doc correction awaits a focused re-review.

The migration locks User, Account and Envelope in one transaction, anchors existing stored balances, then installs INSERT/UPDATE/DELETE capture before unlocking. The User lock drains whole-user erasure. Existing activity count is pinned only to flag incomplete legacy history; it is not replayed. No balance is repaired, clamped or recomputed. Row changes append exact bigint old-to-new deltas. Metadata/no-op updates append nothing; negative balances are preserved. Administrative owner reassignment closes the old owner's position and opens/reopens the new owner's position, retaining isolation and existing ownership-race behavior. No application ownership writer was added.

Headers, positions and entries have tenant composite foreign keys. Transaction-local compass.event_id must refer to the entity owner's event; omitted intent becomes an uncorrelated event. A per-source uniqueness constraint is groundwork, not request deduplication. No production caller sets intent yet. Account and envelope totals are never compared to each other. Planned paycheck allocations and rebalances retain their existing zero account delta; settlement stays unknown.

Openings and entries are immutable to ordinary application SQL. Row deletion closes a position to zero; recreation of the same seed ID reopens the retained position. Whole-user erasure cascades the journal without illegal closing-row foreign keys. Source and journal TRUNCATE and source ID rewriting are refused. Existing Account-to-Transaction deletion restrictions are preserved. Health checks pin all17 trigger definitions and four function bodies, enabled state, replication mode and required privileges. Missing, disabled or altered capture makes the whole report unavailable.

The server-only operator DAL accepts a trusted server-selected tenant ID. It rejects padded/blank IDs and queries only that tenant in one RepeatableRead transaction. DTOs and their arrays are frozen; cents/counts are decimal strings to preserve exact integer values. No UI, endpoint, repair, seed or background automation is added. Flags distinguish unverified_opening, legacy missing_history, missing_opening, journal_gap, removed_entity, uncorrelated and mismatch. A read failure returns a stable code and logs only a bounded Prisma code or unknown, never raw connection/query text.
