**1. Protocol assumes Polar has local access; the recording path has no safe remote mode.** (the mismatch you asked me to assess)
- Where: `AGENTS.md` ("Both apps directly access this repository"), `PROTOCOL.md` ("access the same repository directly"; `claim polar` / `ack polar` / `review polar`), `docs/team/POLAR.md`, `START-POLAR.txt`.
- Facts: the CLI takes the actor as a plain argument. If Codex runs `review polar …` it is indistinguishable from Polar doing it. I confirmed a worse gap with a probe on the reconstruction: after `handoff codex` and `claim polar`, **`review polar ALIGN-01 approved docs/team/impl.md` succeeded using the owner's own handoff file as the "review report"** (exit 0, task `done`). `reportPath` checks only that six marker strings exist; it does not check that `Author:` equals the reviewer, that the path differs from the handoff path, that the verdict in the file matches the argument, or that the report's base commit equals HEAD.
- Required correction (smallest that is honest):
  1. Add a documented **remote review mode**: `review polar <task> <verdict> <report> --recorded-by codex`. Store `recordedBy`, `mode: "remote-proxy"` and `sha256(report)` in `task.review`, and render "recorded by codex for polar (remote)" in COORDINATION.md. Same for `claim`/`ack`.
  2. In `reportPath` for reviews: require `Author:` == actor, path != `handoff.path`, a `Verdict:` line equal to the argument, and `Base commit:` == HEAD.
  3. Proxy may only record a report whose file hash the reviewer's message quotes. For this task, the verbatim text of this report is the artifact.
  4. `team.polar.status` should say `remote reviewer; no local acknowledgement`, not `protocol acknowledged`, unless Polar actually ran the ack. For the record: Polar has read the protocol as delivered in the packet; that is a read acknowledgement only.
  5. Update AGENTS.md / PROTOCOL.md / POLAR.md / START-POLAR.txt with a "local or remote reviewer" paragraph, add a decision revision (e.g. DR-ALIGN-06), and refresh the handoff text that still says desktop delivery failed.
- Interim: until 1-2 land, Codex recording `approved` or `changes_requested` "as polar" is a proxy record of an independent review, and should be described that way. It must not be described as Polar having run the command.

**2. `HANDOVER.md` points to a file that is not in the change.**
- `HANDOVER.md` is a *new* file and says "previous contents are preserved in docs/archive/2026-10-08/HANDOVER.md". The staged archive contains nine files and none is `HANDOVER.md`. The path appears exactly once in the packet (in the pointer itself). Either the archive file is missing from the stage, or the sentence is wrong because HEAD had no `HANDOVER.md`.
- Fix: stage the archive copy if one exists, otherwise reword the pointer. Add a small link check (relative `.md` links in the pointer files and `docs/team/`) to `project-sync check` so this class is caught.

**3. The content fingerprint walks the working directory, not Git, so CI can disagree with local.**
- `fingerprint()` recurses `src/ prisma/ scripts/ tests/ public/ docker/ .github/ .githooks/ compass-landing/` with `readdirSync`. It hashes ignored and untracked files too (`.gitignore` has `_dev_*`, `*.key`, and others). CI sees only tracked files. Any ignored file in those folders gives a different digest locally and in CI, so `project:check` fails on the first push even with a clean tree locally. `check-index` only flags untracked files that are *not* ignored, so it will not catch this.
- This is the least certain finding: I could not see whether such files exist, and `gh` auth was unavailable so CI has never run this change. It is blocking because the gate is the shared enforcement layer.
- Fix: enumerate with `git ls-files -z --cached` (and exclude `src/generated`), or prove it on a clean `git clone` + `pnpm project:check`. Also confirm the `on:` triggers in `ci.yml`: `branch()` fails on any non-`main` branch unless it is a PR, so a `push` trigger on other branches (e.g. Dependabot) would go red.
